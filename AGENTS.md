# AGENTS.md

SvelteKit 3 + Svelte 5 PWA (client-rendered) deployed to Cloudflare Workers. Dual weather providers: US NWS (`/`, `/Weather`) and worldwide Open-Meteo (`/global`, `/global/weather`), with Paraglide i18n (en/es/fr). pnpm-only repo.

## Commands

- `pnpm dev` — local dev (`vite dev`)
- `pnpm check` — typecheck (`precheck` compiles Paraglide first, then `svelte-kit sync && svelte-check`)
- `pnpm format` / `pnpm format:check` — Prettier write / verify (Svelte + Tailwind plugins; config in `prettier.config.js`, ignores in `.prettierignore`)
- `pnpm lint` — ESLint flat config (`eslint.config.js`: JS + non-type-checked TS + Svelte, Prettier-compatible; `svelte-check` remains the type layer)
- `pnpm test` / `pnpm test:watch` / `pnpm test:coverage` — Vitest unit suites (`src/**/*.test.ts`, node env; `/coverage` output is gitignored)
- `pnpm run paraglide` — regenerate `src/lib/paraglide/` from `project.inlang/settings.json` + `messages/*.json` (generated dir is gitignored; CI relies on `precheck`)
- `pnpm build` — production build (`vite build`)
- `pnpm preview` — build + `wrangler dev`
- `pnpm deploy` — build + `wrangler deploy`
- `pnpm cf-typegen` — regenerate `src/worker-configuration.d.ts` via `wrangler types`; never hand-edit that file
- typescript pinned to 6.x — svelte-check 4 rejects TS7 without an experimental dual-install setup; `renovate.json` blocks `>=7`
- Requires pnpm (`preinstall: only-allow pnpm`, `engine-strict=true` in `.npmrc`)

## Architecture

- `src/routes/+page.server.ts` sets `ssr = false; prerender = true` — app is fully client-side. `/Weather/+page.svelte` fetches `api.weather.gov` directly from the browser (points → alerts/forecast/gridpoint); only US NWS-covered locations work.
- `src/routes/+page.svelte` rounds coords to 4 decimals before `goto('/Weather?lat=&lon=')`; city search uses `searchCity()` from `src/lib/openmeteo.ts` directly from the browser (`count=5`, `language="en"`, pick from candidate list) — no server proxy, no Census geocoder.
- `src/service-worker.ts` (typed, excluded from `svelte-check` via `tsconfig.json`) caches `immutable`+`assets` plus the prerendered `/offline` fallback; navigations are network-first with navigation-preload and fall back to `/offline`, other same-origin GETs without query strings are cached (`/reverse` and `?` URLs never cached so forecasts stay fresh). Handles `SKIP_WAITING` messages and broadcasts `SW_UPDATED`. `src/routes/+layout.svelte` imports `#lib/main.css` (Tailwind v4 via `@tailwindcss/vite` + small `@layer base/components` for typography, buttons, cards, inputs, chips, tables; no Pico/Sass toolchain), wires View Transitions, renders header chrome via Paraglide keys (`app_title`, `nav_provider_*`, `nav_language_label`, `nav_units_label` — the °C/°F buttons stay symbolic and the SW update banner stays English), and shows the SW update banner.
- `/Weather/+page.svelte` uses tree-shaken `chart.js` core (no `chart.js/auto`, no `luxon`/`chartjs-adapter-luxon` — dates via `Intl.DateTimeFormat` + category scale), lazy-loads MapLibre via `IntersectionObserver`, caches the last forecast per 4-decimal tile in `localStorage` for offline fallback, and sets/clears the app badge from active alert count. The 24-hour chart is built from raw `/gridpoints` data (`forecastGridData` from `/points`; 7-day text still uses `/forecast`): per-hour slots are expanded from `validTime` intervals with metric→US conversion (°C→°F, km/h→mph); heat-index/wind-chill series render only where NWS provides non-null values.
- Open-Meteo workflow (`src/routes/global/+page.svelte` landing, `src/routes/global/weather/+page.svelte` forecast): city search via Open-Meteo geocoding API directly from the browser (`count=5`, `language=` follows UI locale, pick from candidate list); GPS path reverse-labels through the same-origin `/reverse` proxy (OpenStreetMap Nominatim, `zoom=10`, 10s timeout — direct BigDataCloud calls were blocker-listed and inaccurate, so don't reintroduce them). Forecast via the `openmeteo` npm SDK (`best_match`, `timezone=auto`, `forecast_days=7`, dynamic `import()` so NWS pages never load it): FlatBuffers `hourly.time()` is a scalar start + `interval()`, so `src/lib/openmeteo.ts` expands per-step TRUE UTC instants (do NOT add `utcOffsetSeconds` — that SDK-readme pattern is wall-clock-as-UTC and double-shifts when formatted zoned). No `current=` block — hero uses hour-0 of `hourly`. Page shows hero (temp + feels-like) + 24h chart (temp + apparent-temp + PoP bars via `src/lib/openmeteo-chart.ts`) + ZFP 7-day cards only: no alerts/radar/MapLibre/AFD. Separate `swa:openmeteo:` cache namespace in `src/lib/openmeteo-cache.ts`.
- `src/lib/zfp/` is a framework-free ZFP-style narrative library (pure TS, no Svelte/Paraglide imports; it builds English and post-translates via `translator.ts`, seeded from AWIPS `Translator.py`, see `NOTICE`). Input is always metric; `units.ts` converts only at display. `splitDayNight(series, max, nowMs)` skips ended slots so period 0 contains now (NWS "this afternoon" behavior); night blocks starting before 6am local title as Overnight. Emoji via shared `src/lib/weather-emoji.ts` (moved out of the NWS page; global page matches against English `shortEn`).
- i18n is Paraglide with strategy `["cookie", "localStorage", "baseLocale"]` — NO `url` strategy (keeps `/Weather?lat=&lon=` stable, no locale URL prefixes). `@inlang/plugin-message-format` resolves `pathPattern` relative to repo-root cwd, so Weblate sources live at `./messages/*.json` (not under `project.inlang/`). Import generated code via the `#lib` alias (`#lib/paraglide/messages.js`); `$lib/paraglide/*` and plain-`.ts`-relative imports of it fail `svelte-check` resolution. `src/hooks.server.ts` is a minimal cookie→`%lang%` stamper with hardcoded locale list (comment explains why); `Handle` imports from `@sveltejs/kit/hooks` in SvelteKit 3. Client locale truth lives in `src/lib/prefs.svelte.ts` (`initPrefs()` once, guarded); `src/lib/preferences.ts` holds pure defaults: provider NWS only for `en-US`, units US for any `*-US`, locale from primary subtag.
- Header (`+layout.svelte`) has the NWS/OpenMeteo provider toggle (navigates `/`↔`/global`, persists `swa:provider`), language picker, and units toggle (visible on `/global*`, persists `swa:units`). `/` auto-redirects to `/global` when the resolved provider is Open-Meteo. Stale `landing_*_nws` message keys were removed with the Census workflow — don't re-add NWS-specific landing strings; the NWS landing page hardcodes English.
- `vite.config.ts` `connect-src` additionally allows `api.open-meteo.com`, `geocoding-api.open-meteo.com` (Nominatim is proxied same-origin so needs no entry).
- `vite.config.ts` relies on SvelteKit route splitting + dynamic `import("maplibre-gl")` (do NOT add `manualChunks`: Vite 8 builds the SW with code-splitting off and rejects it). MapLibre worker must load via `maplibre-gl/dist/maplibre-gl-worker.mjs?worker&url` + `setWorkerUrl` (see `Weather/+page.svelte`).
- Svelte 5 runes (`$state`, `$derived`) throughout; `tsconfig.json` has `strict` with `checkJs: false` and excludes `src/service-worker.ts`.
- Unit tests are colocated (`src/**/*.test.ts`, Vitest node env) and typechecked by `svelte-check`, so keep them type-clean (no `any` leaks, no unused imports). `localStorage` is stubbed per-file with an in-memory map; the `openmeteo` SDK is faked via `vi.mock` (see `openmeteo.test.ts` for the UTC-expansion regression pin); `/reverse` server tests call `GET` with a `Parameters<typeof GET>[0]`-cast URL and stubbed `fetch` (the `./$types` import is type-only, so no generated types are needed at runtime). Keep `src/lib/zfp/` framework-free — no Svelte/Paraglide imports, or the node-env suites break.
- `wrangler.jsonc`: `main: .svelte-kit/cloudflare/_worker.js`, adapter is `@sveltejs/adapter-cloudflare`. Custom asset headers live in root `_headers` (required at project root by the adapter); use `pnpm deploy`. `_headers` must NOT set `Content-Security-Policy` — SvelteKit generates it (per-build bootstrap hashes) from `csp` in `vite.config.ts`.
- `.github/workflows/ci.yml` runs `pnpm format:check` + `pnpm lint` + `pnpm test` + `pnpm check` + `pnpm build` (fail-fast order); `dependency-review`/`scorecard` are supply-chain only.
