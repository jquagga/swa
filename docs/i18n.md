# Internationalization

One source of truth: `messages/*.json` via Paraglide. Both the app chrome
(`m.*()` calls in routes) and the Open-Meteo forecast narratives come from
there. The NWS workflow stays English-only (upstream text).

## Architecture

```
messages/{locale}.json
      ↓  pnpm run paraglide (codegen → src/lib/paraglide/, gitignored)
src/lib/zfp-dict.ts :: getZfpDictionary()   ← the only Paraglide→ZFP bridge
      ↓  ZfpDictionary (plain strings + (string)=>string formatters)
src/lib/zfp/*  (framework-free: no Svelte/Paraglide imports)
```

`src/lib/zfp/` never imports Paraglide, so its Vitest suites run in plain
node. The Svelte pages build a dictionary for the current locale and pass
it to `buildForecast(series, { dictionary, units })`. English output
(`narrativeEn`/`shortEn`, used for emoji matching) always comes from
`EN_DICT` in `src/lib/zfp/dictionary.ts`.

`ZfpDictionary` fields map 1:1 to message keys as `zfp_<field>` (function
fields map to messages with matching `{params}`). `withFallback()` merges
a partial dictionary over English — the safety net for locales
mid-translation.

## Dictionary conventions

- Values are **lowercase-initial fragments**; the builder capitalizes
  sentence starts and card labels. Do not pre-capitalize translations.
- `{placeholders}` reorder freely per locale (e.g. `{type} {likely}`).
  The parity test pins placeholder sets per key.
- `zfp_dir_*` entries are **full prepositional phrases** (en `northeast`,
  es `del noreste`, fr `du nord-est`) because articles contract per
  language; the `zfp_wind_with_dir` pattern places them.
- Heavy precipitation uses pre-combined per-kind entries
  (`zfp_heavy_rain`, …) so gender agrees; qualifier adjectives
  (`isolated`/`scattered`/`numerous`) use one invariant form (MVP).
- Unit abbreviations (`mm`, `cm`, `mph`, `kph`) stay untranslated.
- Known MVP simplifications: single-form qualifier adjectives, English
  singular-`inch` rule, Latin-script capitalization, `20s`-style decade
  bands. The `zfp_range`/`zfp_temp_lower|mid|upper` templates let
  translators drop the English `s` suffix.

## Adding a language (no code changes)

1. Add the tag to `locales` in `project.inlang/settings.json`.
2. Copy `messages/en.json` to `messages/<tag>.json` and translate every
   value (keep all `{params}`). Machine-translate first, then human-review
   — especially `zfp_*` fragments and the `zfp_dir_*` prepositions.
3. Run `pnpm run paraglide`, then `pnpm test` — `src/lib/i18n.test.ts`
   fails on missing keys, empty values, dropped placeholders, or
   untranslated plain words.
4. Run `pnpm check` and switch the language picker in the header to verify
   narratives, 7-day cards, chart legend, and period titles re-render.

Detection is automatic: exact tag → primary subtag (`es-MX` → `es`) →
base locale. The header picker lists the configured locales; geocoding
already forwards any tag (primary-subtagged) to Open-Meteo.
